# Tool-assisted play (TAS)

leapemu's emulation is deterministic. The same BaseROM, cartridge, emulation
settings, EEPROM contents and per-frame input always produce the same machine state:
- with any CPU backend (interpreter, cached interpreter, JIT);
- with or without frame interpolation's draw capture;
- at any emulation speed.

An input movie is therefore enough to reproduce a run exactly.

## In the GUI (Tools > Movies)

- **Record...** restarts the game (power-on) and records every frame's input:
  buttons and the stylus. It starts from the current save data;
  **Record from Blank Save...** starts from an empty save instead. The
  console's touch calibration is always kept.
- **Play...** replays a movie from power-on. The BaseROM and cartridge must
  match (checked by CRC). The movie's emulation settings (CPU timing, idle-loop
  skipping) are used while it runs. When it ends, emulation pauses; resuming
  continues with live input.
- **Read-Only:** on while playing, off while recording. Turning it off during
  playback records from the current frame on, replacing the rest of the movie.
- **Rerecording:** a save state made during a movie also stores the movie's input
  up to that frame (a `.lmv` file beside the state).
  - While recording, loading a state rewinds the movie to that state's frame and
    timeline, and counts a rerecord.
  - While playing, loading a state jumps within the movie. If the state came from
    a different timeline, you are warned.
- **Rewind** (hold `` ` ``) also works with movies: while recording, the input after
  the point rewound to is dropped and a rerecord is counted; while playing, the movie
  plays on from there.
- **Frame Advance** (`.`, hold to repeat; Emulation menu) pauses and runs one frame with the input
  held at that moment. Combine it with slow speeds (`-` / `=`, down to 0.25×).
- **Frame Back** (`,`, hold to repeat; Emulation menu) pauses and goes back exactly one frame. It restores the
  latest rewind snapshot at or before that frame (6 frames apart, further apart after
  fast forward) and runs the frames after it again with the input they had: the
  movie's, or the live input, which is logged for the last hour. While recording, the
  movie is cut back to that frame and a rerecord is counted, as with rewinding. It
  needs Emulation > Rewind.
- **Show Counters** shows, in the status bar:
  - the frame number;
  - the lag counter: frames in which the game read neither the buttons nor the
    touch screen;
  - each frame's input, in the movie's notation.

While a movie runs, it uses the EEPROM contents stored in it. Nothing is written to
your `.sav` or calibration files until the next reset or cartridge change. At that
point they are reloaded from disk.

## In the CLI

```sh
# record scripted input
leapemu-cli --bios BIOS --cart GAME.zip --frames 3000 --press a@600-605 \
            --touch 80,80@900-910 --record-movie run.lmv --state-hash

# play it back (runs the movie's length) and print a hash of the final state
leapemu-cli --bios BIOS --cart GAME.zip --movie run.lmv --state-hash
```

`--state-hash` prints a CRC-32 of the final machine state, to check that a movie
syncs. `--movie` plus `--record-movie` re-records a movie, optionally with extra
frames. `--screenshot FILE --shot-every N` and `--audio-out FILE` render a movie
headlessly (for encoding).

## Movie format (`.lmv`)

Plain text, so movies can be edited, generated by scripts and diffed.

```
leapemu-movie 1
bios_crc af05e5a0
cart_crc 3c428a13
cart_title Pet Pals - Animal Nurturing
timing 0 0 0.75 1.5 1 2 0 0 1.5 1.5 0 0 32 2 0 0
idle_skip 1
allow_unsigned 0
auto_calibrate 1
system_eeprom <512 bytes as hex>
cart_eeprom <2048 bytes as hex>
rerecords 12
author ...
comment ...
input
...............|
....A..........|
...............|80,79
```

The header holds:
- the emulation settings (the CPU timing model's wait states, in the order of
  `Machine::Timing`);
- the power-on contents of the system and cartridge EEPROMs.

After `input` comes one line per frame, starting at the first frame after power-on:
- one column per button: the letter when pressed, `.` otherwise:

  | Column | Letter | Button |
  |---|---|---|
  | 1–4 | `U` `D` `L` `R` | the D-pad |
  | 5–6 | `A` `B` | A, B |
  | 7 | `H` | Hint |
  | 8 | `P` | Pause |
  | 9 | `E` | Home |
  | 10–11 | `v` `V` | volume down / up |
  | 12–13 | `k` `K` | brightness down / up |
  | 14 | `c` | contrast |
  | 15 | `O` | the power switch is off |
- then `|` and, when the stylus is touching, its position `x,y` in screen pixels
  (0–159).

Lines with only the 14 button columns (from before the power column existed) are
read with the power switch on.

Unknown header keys are ignored, so later versions can add some.

While the BaseROM's touch calibration runs, the automatic calibration tapper
controls the stylus, unless the movie touches the screen itself. This is
deterministic, so a movie that starts without calibration data still syncs.

## How it works

**What makes a run reproducible.** Nothing in emulation depends on the host: no
wall-clock time, no randomness, no threads. Devices advance only with emulated
cycles. Everything else that changes the machine state is part of the movie:
- the power-on contents of both EEPROMs (the save, and the console's own settings and
  touch calibration);
- the settings that change emulation: the wait-state timing, idle-loop skipping
  (it changes the exact state, [hardware.md](hardware.md#the-idle-loop-and-skipping-it-leapemu)),
  the unsigned patches, ROM patches (`cart_patches`), the Leapster 2 services and the
  automatic touch calibration.

Display features (interpolation, vector scaling, filters) only observe, so they
change nothing.

**Save states** (`src/core/state.h`): each component has one `serialize` function,
used both to write and to read, so the two cannot drift apart. Every field is written
on its own: an early version copied whole structures, and their padding bytes (left
uninitialised) made equal states hash differently. A state starts with a format
version; when a version adds state, older files load with the value the BaseROM
would have set (the interrupt enables of version 8, for example, default to what the
BaseROM writes at boot).

**Save data belongs to the cartridge.** Loading a cartridge clears the cartridge
EEPROM before its `.sav` is read, and only a reset keeps it. An early version kept it
across a cartridge change, and wrote the previous game's save under the new game's
name.

**Rewind** (`src/core/rewind.h`): a snapshot every 6 frames. Only the newest is kept
whole; each older one is stored as its XOR difference from the next, run-length
coded. Most of memory does not change in a tenth of a second, so a snapshot costs
about 11 KB, and 256 MB holds about half an hour. Taking one takes about 3 ms (the
RAM is compared in one pass with `memcmp`).

**Frame back** restores the newest snapshot at or before the frame wanted, then runs
the frames after it again with the input they had: the movie's, or the live input,
which is logged for the last hour. The result is the exact earlier state, not an
approximation, which is also why it needs rewind turned on.
